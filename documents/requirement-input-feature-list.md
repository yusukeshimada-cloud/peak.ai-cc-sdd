# 要件インプット-機能一覧表

`spec-init --list memo.md` の入力として `memo.md` を確認し、以下の観点で機能粒度を見直して作成した。

- 1つの機能に複数のビジネス機能が包含されていないか
- 同じビジネス機能を構成するが技術レイヤーごとに機能が分かれていないか
- 1機能の `tasks.md` が 10-15 ステップ程度にとどまるサイズか
- 共通仕様等が個別機能に内包されず切り出されているか

## 判定メモ

| 観点 | 結果 |
|------|------|
| 複数業務の包含 | `ログイン / ログアウト`、`コメント表示 / コメント投稿`、`記事一覧 / 帳票出力` を分離した。 |
| 技術レイヤー分割 | フロントエンド / バックエンドを別機能として数えず、ビジネス機能単位で一本化した。 |
| タスク粒度 | 記事機能を `一覧 / 詳細 / 作成 / 編集 / 下書き / 帳票` に分け、過大化を防いだ。 |
| 共通仕様の切り出し | 認証・認可共通とユーザー変更連携を個別機能から分離した。 |
