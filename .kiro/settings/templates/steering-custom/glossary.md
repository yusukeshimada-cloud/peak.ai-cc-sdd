# Glossary Standards

[Purpose: keep project-wide terminology stable across requirements, design, and implementation]

## Scope
- Business terms
- Product-specific terms
- Technical terms that are used repeatedly in specs and steering

## Entry Rules
- Each term should have one preferred name
- If abbreviations are used, include the full name and intended meaning
- If a term has a narrow project-specific meaning, state it explicitly

## Maintenance Rules
- Prefer updating the shared glossary over redefining the same term in feature documents
- Keep terms concise and stable
- Add entries when a repeated term could be interpreted multiple ways

---
_Focus on shared terminology, not exhaustive domain dictionaries._
